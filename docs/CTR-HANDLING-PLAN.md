# CTR handling module: investigation and implementation plan

Initial status: planning only; see the implementation status at the end of this document. CTR source is authoritative for its own rules; the player guide describes intended experience. TK2's current native bodies and runtime observations are required before adapting them.

## Goal and boundaries

An opt-in, offline-only local-human Studio module that makes TK2's driving, drifting and reserve management feel recognizably like original NTSC CTR. Retain TK2 track collision, items and presentation unless a specific CTR behavior can be mapped and tested. Preserve mandatory online protection and default the module off. The existing Mid-air Jump Drift module remains separately selectable; avoid applying its jump/trick rules twice. Prioritize an honest playable approximation; a full engine and collision replacement is a separate, much larger project.

## Evidence gathered

- `Github/ctr-native/game/Vehicle/VehFire.c:100,298-372`: fire-cap selection depends on prior reserves, the stronger cap, and a super-pad condition; pads/powerups use an outside timer and reserve delta, ordinary drift/hangtime boosts add, and super engine applies a minimum. Do not implement all events as identical additions or unconditional max fire.
- `VehPhysProc.c:251-259` decrements positive signed reserves; `:945-962` shows brake-related reserve clearing subject to the pad condition; `:2475-2542` handles drift meter conversion and limits attempts. Other reset and damage branches must be traced, not inferred from the brake branch alone.
- `VehPhysGeneral.c` contains vehicle angular steering, slope and jump/friction impulses; its fixed-point arithmetic, frame rate, character constants and order of operations need extraction before mapping to Unity.
- Player guide sections 2–5 describe three drift boosts, charge-dependent reserves, stronger fire priority, the super-pad exception, speed above the soft cap, surface effects, air friction and buffered jumping. Values are player explanations and test targets, not a substitute for branch-level source verification.
- `src/Reconstructed/BoostLogic.cs` describes an earlier reviewed TK2 reserve/boost calculation, not original C# or proof of current native execution. `local/midair-drift-evidence/Ant_BoostManager__OnKartLandedAfterPlayerTriggeredJump.c` shows the current landing callback invokes native boost/reserve paths. Current `local/Ant_BoostManager-current.txt` and `local/PixelKartPhysics-current.txt` expose candidate fields/signatures, not method bodies. Verify they still match the installed game before use.

## Implementation sequence

1. **Reference model and fixtures.** Trace `VehFire_Increment` and every caller for start, drift, hangtime, normal/super pads, powerups and reset/collision events. Record fire values, reserve increments, timer conditions, integer widths, overflow, frame timing, boost-meter windows and relevant character classes. Create deterministic CTR-source-derived event and movement traces, including NTSC timing. Label any missing constants or unsupported event explicitly. Test boundary behavior before connecting TK2.
2. **Installed-game mapping.** Verify the current `GameAssembly.dll` and interop provenance; export exact Ghidra bodies for `Ant_BoostManager` boost entry, pad, landing, reserve decay, wall and speed-cap calculations, and `PixelKartPhysics` velocity, acceleration, friction, jump and steering boundaries. Trace actual callers and inlining, including collision, pad contact/exit and hit paths. Resolve complete runtime signatures against installed interop; isolate unsupported hooks instead of relying on binary-hash allowlists.
3. **Measure before replacing.** Add temporary, opt-in, rate-limited offline diagnostics for local input, fixed-step delta, grounded/surface state, actual velocity, drift meter/boost index, pad contact, current TK2 reserve and boost contributions. Capture repeatable user-driven flat acceleration, drift, ramp, pad, brake and wall scenarios. Use actual pad contact/exit, not a guessed boost-duration timer, for freeze semantics. Establish CTR-to-TK2 scale from measured speed/time and track geometry; CTR display values are not metres per second.
4. **Reserve and fire vertical slice.** Implement a pure per-player CTR state machine with source-derived boost events, strongest-fire priority, super-pad replacement condition, charge-based reserve gains, pad contact rules, decay and clearing. Test exact edge cases, frame rates, simultaneous events and signed-overflow behavior against reference fixtures. Keep fire and reserves distinct. Decide deliberately whether authentic signed overflow is exposed or documented as deferred; do not silently advertise SAFFI support.
5. **TK2 adapter.** Route only verified local boost events once into that state machine and map its active fire to a calibrated TK2 speed contribution. Prevent native reserve/boost contributions from double-counting while retaining required HUD, audio and native event effects. Ensure triggering mini-turbos remains manual, the meter and its three attempts follow the selected CTR model, and normal pads, super pads, landing boosts, items and start boosts are explicitly classified. If TK2 cannot distinguish an event reliably, leave it unsupported and surface that limitation.
6. **Driving feel.** Add grounded acceleration, turning/drift steering, longitudinal and lateral friction, air drag, slope handling and overspeed decay in measured stages. Preserve above-soft-cap velocity so speedghosts and froggying remain possible; avoid clamping every frame to the soft cap. Use native collision sweeps and surface classification. Tune against reference traces and user feedback for flat road, airborne, slopes, road/offroad/ice, braking, U-turn and collisions. Keep initial class choice grounded in CTR source; defer class menu until one baseline drives acceptably.
7. **Jump/drift integration.** Compare CTR source buffer and coyote/cooldown timings with the existing Mid-air Jump Drift module. Define one owner for buffered input and landing eligibility when both are enabled; keep ordinary jumps, clean drift, buffered hops and three airborne turbos distinct. Preserve native trigger/UI behavior or document any unavoidable difference. Verify against current inlined call boundaries.
8. **Lifecycle and conflicts.** Reset module-owned state on race reset, pause/menu transition, finish, respawn, teleport, replay, scene change, disable and errors. Restore only values actually owned by the module. Explicitly handle snapshots/rewind, Fast Fall, AutoBoost, kart tuning, advanced physics overrides, Antigravity and items: define precedence or block incompatible combinations visibly. Avoid changes to AI, remote racers, leaderboard replays and online rooms. Add no new online allowlist entry.
9. **Studio and diagnostics.** Add one default-off gameplay module with clear description, restrained user-facing status for fire tier and reserve time, and a source/evidence guide. Keep experimental calibration and raw traces optional and bounded. Include its source dependencies in module exports and ensure configuration reload and installation behave correctly.
10. **Verification.** Run reference-state tests, hook signature checks against installed interop, plugin build, relevant Python/UI tests and actual Studio smoke. Test disabled, online, AI, replay and recovery guards. Player-run offline scenarios: baseline acceleration/top speed; first/second/third full and early boosts; pad freeze and super-fire replacement; hangtime boost; brake/wall reset; airborne speed retention and slopes; drift release; simultaneous events; existing mid-air feature; pause/respawn/rewind; multiple frame rates. Compare trace timelines and measured speeds to baseline/reference. Require visible HUD and steering behavior, not just logs or a successful build.

## Key unknowns and decisions

- Exact fixed-point-to-Unity scale and frame scheduling require measurement; do not copy CTR's speed values directly.
- Current TK2 native calls may inline candidate methods; event source and collision provenance are not yet confirmed.
- The CTR source's pad outside timer is more nuanced than a blanket freeze and must be reproduced from full callers.
- Full collision topology, track surface semantics, map-specific speed impacts, original character stats and obscure overflow quirks may not have exact TK2 equivalents. Maintain a source-to-adapter coverage ledger and mark full, partial, omitted and runtime-validated separately.
- No gameplay fidelity, current hook compatibility or in-game success is claimed until the staged evidence and player tests exist.

## Implementation status, 2026-10-28

The first testable adaptation implements a seconds-based fire model, native boost event adapter, scoped ground acceleration/friction adjustments and Studio controls. It does not complete the full plan: physical pad freeze, super pads, wall resets, exact drift timing, exact CTR steering and fixed-point overflow remain unimplemented. Calibration and live validation remain open. See `CTR-HANDLING.md`.

# Gamepad viewer

The Gamepad viewer is a read-only in-game HUD card for driving input. Enable **Gamepad viewer** in Toolkit → Mod packs. It appears automatically when local race or leaderboard replay input is available. Press the configured hotkey (default **F9**) to hide or show it; the screen position, size and background opacity are adjustable in the module settings.

The card reads the game's post-mapping racing input, so steering and action states work across Rewired-supported controllers and keyboard controls without assuming Xbox button numbers. It shows steering and throttle/reverse as normalized meters, plus jump, drift, boost, item, brake, look-back, target switching and weapon pickup states. The live source label uses Rewired's last active controller when that API is available.

During ghost playback, the card switches to `PTK_PlayerReplayInput_ReplaySerializer` and reads the input values already being applied by replay playback. The game records semantic actions and axes, not the physical keyboard/controller type or its original button labels; replay cards therefore identify their source as **RECORDED** rather than claiming to know the device. If replay input data has not arrived, the overlay stays hidden until the serializer reports data.

The runtime implementation is `plugins/TK2.Customization/GamepadOverlay.cs`; the normalized display model is `InputOverlayModel.cs`. The built-in module catalog exposes settings before first launch. Showing only your own live input is allowlisted. Recorded ghost actions expose extra racing information, so enabling **Show leaderboard ghost inputs** causes mandatory online protection to block leaderboard uploads and online-room actions. Turn that option off to keep the live-only viewer available online. The module does not change input, physics, items or replay data.

Current-build evidence: `Ant_KartInput.ProcessRacingInput` registers local input data with `PTK_PlayerReplayInput_ReplaySerializer.RegisterCurrentInputForReplaySerializeSet`; ghost processing calls `ProcessAndSetPlayerInputFromReplay`. Serializer metadata exposes applied steering/acceleration and the corresponding discrete actions (`PTK_PlayerReplayInput_ReplaySerializer`, TypeDefIndex 1165; replay input functions around `0x180617330` and `0x180617490`). Ghidra pseudocode is approximate native C-like output, and these declarations alone do not certify visible behavior in a running game. Verify the appearance and replay-source selection in a local race and leaderboard playback before relying on the UI.

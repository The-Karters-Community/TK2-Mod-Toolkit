# Gamepad viewer

The Gamepad viewer is a read-only in-game HUD card for driving input. Enable **Gamepad viewer** in Toolkit → Mod packs. It appears automatically when local race or leaderboard replay input is available. Press the configured hotkey (default **F9**) to hide or show it; the screen position, size and background opacity are adjustable in the module settings.

The live viewer reads steering and throttle/reverse from the game's racing input and reads Drift and Boost from the named Rewired actions (`Drift_left_right` and `Boost`). This distinction matters because the game rewrites its gameplay Drift/Boost fields when it swaps boost-key behavior; those post-processed fields can report a held Boost binding as Drift. Reading the mapped Rewired actions preserves the action the player actually bound for both keyboard and controller. It shows the axes, jump, drift, boost and item actions in an input-focused HUD. The live source label uses Rewired's last active controller when that API is available.

During ghost playback, the card switches to `PTK_PlayerReplayInput_ReplaySerializer` and reads the input values already being applied by replay playback. The game records semantic gameplay actions and axes, not the physical keyboard/controller type or original button bindings; replay cards therefore identify their source as **GHOST** and label the actions as recorded game actions. If replay input data has not arrived, the overlay stays hidden until the serializer reports data.

The runtime implementation is `plugins/TK2.Customization/GamepadOverlay.cs`; the normalized display model is `InputOverlayModel.cs`. The built-in module catalog exposes settings before first launch. Showing only your own live input is allowlisted. Recorded ghost actions expose extra racing information, so enabling **Show leaderboard ghost inputs** causes mandatory online protection to block leaderboard uploads and online-room actions. Turn that option off to keep the live-only viewer available online. The module does not change input, physics, items or replay data.

Current-build evidence: `Ant_KartInput.ProcessRacingInput` reads the named Rewired actions, rewrites gameplay Drift/Boost fields based on `bUseSwappedBoostKey`, then registers that processed `inputData` with `PTK_PlayerReplayInput_ReplaySerializer.RegisterCurrentInputForReplaySerializeSet`. Ghost processing applies the serialized values through `ProcessAndSetPlayerInputFromReplay`. Serializer metadata exposes applied steering/acceleration and corresponding discrete actions (`PTK_PlayerReplayInput_ReplaySerializer`, TypeDefIndex 1165; replay input functions around `0x180617330` and `0x180617490`). Ghidra pseudocode is approximate native C-like output, and these declarations alone do not certify visible behavior in a running game. Validate the live Drift/Boost labels with the player's swapped bindings and check the HUD in both a local race and leaderboard playback.

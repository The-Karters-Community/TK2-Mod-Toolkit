# Your first mod in TK2 Mod Toolkit

Start with **Workshop → First mod tutorial → Create MyKartHop recipe**. This creates `plugins/TK2.Customization/Recipes/MyKartHop.cs`, opens Module editor, and selects its files. If that name exists, choose another name in the editor's Create a new module field. Recipes are ordinary C# files in the same project, discovered through `IModRecipe` when the compiled plugin loads.

| Method | Purpose |
| --- | --- |
| `Configure(ConfigFile config)` | Declare defaults, descriptions and allowed ranges. |
| `Tick()` | Apply behavior each frame while enabled. |
| `Restore()` | Undo persistent changes when disabled or disallowed. |

`ChangesGameplay = true` selects the host's offline/local gameplay guard. The template also checks that a race is running, the game is not paused, the shortcut was pressed, and the kart belongs to a local human player. Keep those checks.

Change the default `UpwardVelocity` from `6f` to `8f` in Configure. Its allowed range is 0–30. The template uses our public adapter:

```csharp
ReadableGame.AddVelocity(kart, Vector3.up * _hop.Value);
```

The adapter calls the reviewed C# translation in `src/Reconstructed/KartLogic.cs` and writes the result to the current game's kart object. Search **AddVelocity** under **Game API reference → Kart & driving** to inspect the signature and open that implementation. Other catalog entries may have only declarations, not recovered implementations. Check access level and complete signature before calling or hooking game methods. Existing adapters demonstrate how our public recipe API interacts with internal native objects.

Choose **Save C#**, close the game and choose **Build & install**. This requires the .NET SDK and interop generated by the game's first BepInEx run. Failed compilation leaves the installed DLL untouched; Compiler output identifies the file and line. Start the game yourself, enable **My Kart Hop** under **Mod packs → Your recipes**, and save. Press F9 during a local race.

After the module has been built and loaded once, adjust strength or toggle without compiling: **Save changes** updates `BepInEx/config/local.tk2.customization.cfg`, which the running plugin checks every half second. Source defaults initialize missing config entries; changing a default does not overwrite an existing value. Reset module restores the defaults declared by the loaded plugin.

For a built-in module, expand it and choose **Edit code**. Camera setup opens behavior, settings and panel files; HUD and tuning share implementation files. **Open folder** opens the source directory for your own editor. **Reload file** reads external changes. A conflicting source save is blocked to preserve the external edit; your editor text stays available to copy before reloading. Source backups are in `local/source-backups/` beside the application.

Ideas after the first hop works:

- Add a configurable cooldown using `Time.unscaledTime` so repeated actions cannot accumulate impulses too quickly.
- Split the impulse into forward and upward strengths; start with conservative ranges and test the local kart.
- Tune Camera setup with F8 before editing CameraSettings/CameraFeature, then add a favorite framing preset.
- Create a quiet practice audio preset using AudioFeature's captured-original restoration pattern.
- Inspect `Recipes/FrameLimiter.cs` for a non-gameplay example that restores FPS and VSync.

The installed DLL is a compiled result, not an editable source directory. Code edits need build/install/restart; settings edits need only saving config. Build the application executable with **Build Toolkit.cmd** or `tools/build_toolkit.ps1`; use `-RebuildPlugin` when packaging changed plugin source. These scripts neither launch nor install the game.
